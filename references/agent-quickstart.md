# 新手 Agent 上手与验收模板

本页给不熟悉 Agent 的同事使用。先照流程执行，再按项目事实替换占位内容。

## 首次使用：让 Codex 自动看见全部三个技能

安装本 Skill 后，Agent 需要图生图或电商模板时，应先自行检查同级 skills 目录是否已有 `codesonline-image` 与 `ecom-details-image`。若缺失，且本 Skill 内有 `companion-skills/`，应运行：

```powershell
python "<本技能目录>\scripts\install_companion_skills.py"
```

该脚本只安装缺失的同级技能；不会覆盖已安装技能，也不会携带真实 `.env`、API Key 或生成图片。安装完成后，Agent 再读取相应的 `SKILL.md`。同事只需安装主技能，无需手动拆分目录或记忆两个子技能的名称。

## 新手六步

1. 阅读 `SKILL.md`，再阅读本页和与项目匹配的 reference。
2. 整理 `product-facts.json`：把现货、定制、客户案例、价格、MOQ、交期和证据分开；不确定字段写“待确认”。
3. 锁定 Campaign Style Lock 和页面职责；先确定文案和尺寸，再生图。
4. 判断是否启动子 Agent：事实或文案未锁定时暂停；只有两张以上彼此独立、素材和输出路径都已锁定的图片才并行启动。
5. 用户明确同意外部上传后，才调用 CodesOnline；否则使用本地裁切、抠图、合成或等待授权。
6. 主 Agent 查看每张成图，完成尺寸、事实、物理关系、禁词和 200 px 可读性 QA，再交付最终文件列表。

## 是否启动子 Agent

| 情况 | 做法 |
| --- | --- |
| 0–1 张图，或事实/文案/授权未确认 | 主 Agent 直接处理或先澄清，不启动子 Agent |
| 2 张以上独立图片，素材、事实、尺寸和输出名已锁定 | 每张图或每组独立素材启动 1 个子 Agent 并行 |
| 同一张图需要多个方向 | 由 1 个 Agent 负责一个明确版本，不让子 Agent 再分叉 |
| 需要上传真实照片到外部服务 | 主 Agent 逐文件向用户取得授权；子 Agent 不得使用转述授权 |

## 可复制的子 Agent 交接消息

```text
使用 1688-ecom-image-pipeline；若需外部图生图，再读取 codesonline-image。

目标：制作 [页面编号/用途]
输入：
- [素材绝对路径 1]
- [素材绝对路径 2]
输出：
- [输出绝对路径和文件名]
已确认事实：[产品、材质、工艺、价格/MOQ/交期、适配]
Campaign Style Lock：[色板、光线、背景、字体、构图]
画布：[宽×高]
允许改动：[裁切、抠图、产品外背景、确定性文字排版]
禁止改动：[产品字符、图案、颜色、纹理、数量、比例、结构]
禁用词/禁用路径：[列出本项目错误词]
需读取的技能：[技能路径]
外部上传授权：[未授权 / 已逐文件授权；列出文件]
验收：[产品完整、自然接触阴影、光照一致、无穿插、200px可读]
回报：实际尺寸、文件是否非空、脚本/命令、QA问题和是否需要返修。
```

## CodesOnline 选择规则

- 用户明确点名 CodesOnline 或明确同意外部图生图时才使用。
- 有真实参考图使用 image-editing；无参考图才使用 text-to-image。
- 显式指定 `--size`、`--quality high`、`--style natural`；产品图只允许改背景/氛围，不允许重绘产品。
- 不在 Prompt 中放最终中文价格、MOQ、交期或认证；这些信息由确定性后期排版完成。
- 生成后必须检查本地文件存在且非空。服务返回 URL 不等于交付成功。
- 若图案、文字、结构、物理关系明显错误，最多收窄 Prompt 重试一次；仍失败时按“本地重排版 → 干净背景 → 局部合成 → 报告阻塞”回退。

示例命令（不要把密钥写入命令或 Prompt）：

```powershell
python "$env:CODEX_HOME\skills\codesonline-image\scripts\generate_image.py" `
  --prompt "只扩展产品以外背景，保留真实键帽字符、图案、颜色和纹理；暖米白与石墨灰桌搭；无文字" `
  --image ".\product.jpg" --size "1800x1800" --quality high --style natural `
  --response-format b64_json --output ".\M01-final.png"
```

## 统一页面职责矩阵

| 页面 | 默认职责 | 关键提醒 |
| --- | --- | --- |
| M01 | 产品/品类/核心采购入口 | 标题简短，价格不要塞满主图 |
| M02 | 现货键位图或整套展示 | 使用买家可读的“键位图”，不要默认写 Kitting |
| M03 | 材质、工艺、微距细节 | 放大内容必须来自真实产品局部 |
| M04 | 客户案例或定制效果 | 案例不等同现货配置；检查道具物理关系 |
| M05 | 白底商品、包装或交付证据 | 优先保证整套识别 |
| D01 | 采购入口与阶梯报价 | 现货/定制分开列价 |
| D02 | 卖点、材质、工艺 | 实拍优先，避免重复键位图 |
| D03 | 规格与适配 | 写清“约”“大部分”等边界 |
| D04 | 定制准入、案例、生产质检、交付 | 信息多时可保持宽度并纵向加长 |
| D05–D07 | 流程、证据、FAQ | 按当前项目 brief 启用，不强行补齐 |

项目 brief 优先于本矩阵：如果用户重新定义 M02/M03 的职责，以当前项目确认文案为准，不照抄通用示例。

## 主 Agent 验收回报格式

```text
文件：
- 路径：...
- 存在/字节数：...
- 实际尺寸：...

查看结论：产品是否完整；图案/文字/颜色/数量/比例是否保持；接触阴影、光向、支撑和道具关系是否自然。
事实检查：价格、MOQ、单位、交期和流程是否来自已确认事实；禁词扫描结果：...
移动端：缩小到约 200 px 后，产品和关键采购信息是否可读。
结论：通过 / 返修 / 阻塞；若返修，列出具体位置和原因。
```

失败时回到主 Agent，不要让子 Agent 自行扩大范围、修改共享事实或继续尝试外部上传。
